# Cooked materials and shaders

Cooked materials load with the game's own compiled shaders; no DDC lookup and no shader compile happens for them.

## Load path

- A cooked material carries its inline shader map (`bContainsInlineShaders`, set in `FMaterial::SetInlineShaderMap`). `UMaterial::Serialize` reaches `SerializeInlineShaderMaps`; `ProcessSerializedInlineShaderMaps` keeps only maps whose platform equals `GMaxRHIShaderPlatform`.
- Shader code comes from the game's shader libraries (`.ushaderbytecode`, IoStore variant, stock 5.7.4 `FIoStoreShaderCodeArchiveHeader`): library `DeadByDaylight` (13,193 shader maps, 164,124 shaders) and `Global` (605 maps, 4,741 shaders). Both are opened after `GEngine->Init` by `[ShaderLibrary] Name` of `engine.ini`.
- Only `PCD3D_SM5` shaders exist. The editor must run with `-d3d12 -sm5` or `-d3d11`; the D3D12 default (SM6) silently drops the SM5 maps. `-nullrhi` discards the maps.
- The project's `Config\DefaultEngine.ini` `[/Script/Engine.RendererSettings]` must set `r.AllowStaticLighting=False`, `r.SupportStationarySkylight=False`, `r.SupportLowQualityLightmaps=False` and `r.DBuffer=False` ([profile-format.md](profile-format.md#project-requirements)). The game cooked no permutations for these features. Without them, lit opaque materials miss `TBasePassPSFNoLightMapPolicySkylight` and decal materials miss `FDeferredDecalEmissivePS`; both fall back to the default material.
- A map missing a permutation logs `Incomplete material X, missing (...)` and the material falls back to the default material on every draw; the base pass can still draw for the permutations that exist.

## Guard predicate

`IsCookedWithoutEditorSource()` (`Materials/CookedMaterialGuard.h`), gated by CVar `r.CookedShaders.GuardCookedMaterials` (-1 automatic: on when a shader library is configured), applies the cooked-material behaviour in `Material.cpp`, `MaterialShared.cpp` (no `CacheShaders` compile) and `MaterialInstance.cpp` (static permutation rules). Cooked assets open in the asset editors because the asset editor and content browser gates are lifted while `Modkit::IsActive()`; changes are saved as project assets, never into the game's packages.

## Layout hashes

- Memory image layouts (type name, field offsets, base hashes, SHA1) must match the cooked data. `FMaterialShaderMapContent`, `FMeshMaterialShaderMap`, `FGlobalShaderMapContent`, `FShaderMapContent` and `FNiagaraShaderMapContent` are listed under `[ShaderLayout] TolerateMismatch`: the game's `FShaderMapContent` has an extra 8 byte field, which the `game/dbd` branch holds as the `uint64` placeholder `BHVRUnknown`. The log line `tolerating layout hash mismatch` for these types is expected.
- Uniform buffer layout hash must equal `ResourceTableLayoutHashes[slot]` of the shader. 24 uniform buffer layouts of the game differ from the editor's, all by added members (among them View, FogStruct, ForwardLightStruct, SceneTexturesStruct and the base pass, shadow depth, decal and distortion pass buffers). The profile file `uniform_layouts.txt` describes them and the engine translates the editor buffers to them (below). `AliasUniformBuffers=true` registers cooked layout hashes as aliases of the editor uniform buffer of the same name (`RHICore/RHICoreUniformBufferAlias.h`, D3D12 only); static uniform buffer validation passes through the alias.

How both kinds of layout are compared with a new game version: [game-update.md](game-update.md).

## Uniform buffer translation

- `RHIUniformBufferTranslation.h/.cpp` (RHI) is a registry keyed by editor layout hash. An entry holds the game layout (a normal `FRHIUniformBufferLayout`, resource table in game order), the copy runs from editor to game constant data and the default resource for each game resource the editor lacks.
- `UniformBufferTranslationLoader.cpp` (RenderCore) reads `<profile dir>\uniform_layouts.txt` from `FRenderResource::InitPreRHIResources` when the modkit is active. Without the file nothing is registered. The log line `Uniform buffer translations: N of M layouts registered from '<path>'` reports the result; DBD 10.2.2 registers 24 of 24.
- D3D12: creating a uniform buffer whose layout has a translation also creates a game-layout twin (`TwinUniformBuffer`, `D3D12Resources.h`); every update of the buffer updates the twin. `BindUniformBuffer` binds the twin when the shader's `ResourceTableLayoutHashes` entry equals the twin's hash. Static uniform buffers bind through the same path.
- Runtime content of a twin: the editor bytes of every member with an editor counterpart are copied to the game offset; each added resource holds its default; everything else is zero.
- Without the file the editor fails on 59 of the 200 materials of the material sweep (layout hash ensure, then access violations).

### uniform_layouts.txt

Generated by `uniform_layouts` (`oatmealf-5.7`, `src/bin/uniform_layouts.rs`) from the game capture `game-layouts.json` and the stock editor capture `editor-layouts.json` ([game-update.md](game-update.md)). Text, one record per line; blank lines and lines starting with `#` are ignored; fields are separated by spaces and names contain no spaces; numbers are decimal or `0x` hex.

```
layout <Name> editor=<hash> game=<hash> size=<bytes> flags=<n> binding=<n> static=<n> rtoffset=<n>
leaf <GameOffset> <Type> <Size> <Default|-> <Path>
list <R|G|T|B|U|N> <Path> [<Path> ...]
end
```

- `layout` starts a record. `editor` is the RHI hash of the editor layout (`FRHIUniformBufferLayout::GetHash`), `game` the RHI hash the game's shaders expect, `size` the game `ConstantBufferSize`. `flags`, `binding` (`EUniformBufferBindingFlags`), `static` (`FUniformBufferStaticSlot`, 255 when none) and `rtoffset` (`RenderTargetsOffset`, 65535 when none) are the game values.
- `leaf` lists every constant and resource member of the game struct. `GameOffset` is the absolute offset in the game constant data. `Type` is `FLOAT32`, `INT32`, `UINT32` (constants) or `SAMPLER`, `SRV`, `TEXTURE`, `UAV`, `RDG_TEXTURE`, `RDG_TEXTURE_SRV`, `RDG_TEXTURE_UAV`, `RDG_BUFFER_SRV`, `RDG_BUFFER_UAV` (resources, 8 bytes each). `Size` is the byte size (constant arrays: 16 byte element stride times count). `Default` is the key of the resource used when the member has no editor counterpart, `-` for constants.
- Default keys: `black_texture`, `white_texture`, `black_cube`, `black_srv`, `black_buffer_srv`, `point_sampler`.
- `list` gives the members of one RHI layout array in the game's order: `R` Resources (every resource leaf exactly once), `G` GraphResources, `T` GraphTextures, `B` GraphBuffers, `U` GraphUniformBuffers, `N` UniformBuffers. Lists are optional and repeated lines append.
- `Path` is the flattened member name of the editor metadata (`FShaderParametersMetadata`): `Name`; `Parent.Name` for a member of a nested or included struct; `Name[i]` for an element of a resource array; `Name` for a whole constant array; `Name[i].Child` for a member of a struct array element.

The loader registers an entry only when all of these hold; otherwise it logs an error naming the layout and skips it:
1. The record parses and every `list` entry names a resource leaf.
2. An editor uniform buffer with layout hash `editor` exists, and its `static` and `binding` values are equal.
3. Every editor member has a leaf with the same path, type and size (only additive changes translate).
4. The game layout built from the record recomputes to `game` (`FRHIUniformBufferLayoutInitializer::ComputeHash`), and `game` differs from `editor`.
5. Each leaf without an editor counterpart is a resource with a registered default key; constants without a counterpart are zero.

## BHVR-only shader types

`TCustomVS` (vertex), `FCustomNoDepthPS` (pixel), the pipelines `CustomNoDepthPipeline` and `CustomNoPixelPipeline`, and the vertex factory `FGPUCullingInstancedStaticMeshVertexFactory` do not exist in the editor. Unknown shader types load as null `TMemoryImagePtr<FShader>` slots (Verbose `Unknown TypeLayout`); their passes are not rendered. `ShaderMap.cpp` list/validate paths are null safe.

## Renderer behaviour for cooked shaders

- Niagara GPU script shader maps load: `FNiagaraShaderMapContent` has the game's sizes and offsets and differs only in the layout hash. Whether GPU emitters render correctly is not verified.
- Translucency lighting volume: a cooked `FTranslucentLightingInjectPS` whose parameter layout hash differs from the editor's is not drawn, because the game's `FVolumeShadowingShaderParameters` has 4 extra members. It logs once `Modkit: cooked FTranslucentLightingInjectPS has another parameter layout; translucency lighting volume injection of such lights is skipped.` Lights with that shader do not light translucent surfaces through the translucency lighting volume.
- Light functions: the cooked light function vertex shader lacks the `TEXCOORD0` output its cooked pixel shader declares, and D3D12 rejects that pair. The shadow-mask light function pass is therefore drawn with the editor's deferred light (stenciling) vertex shader. It logs once `Modkit: cooked light function pixel shaders are drawn with the editor stenciling vertex shader.`
- APEX cloth vertex factory: `M_CAMPER`, `M_CAMPER_CUST`, `M_Slasher` and `M_Slasher_Burn` miss `TShadowDepthPS...` permutations and fall back to the default material.

## Material instances

- Scalar, vector and texture overrides on a MIC with a cooked parent need no permutation and no compile: values come from the MIC overrides, then the parent chain, then the cooked default value blob; textures come from the cooked referenced textures.
- Static switch and base property overrides need a permutation the cooked data cannot supply and are blocked for cooked parents (`IsStaticPermutationAllowedForCandidateParent`).
- The MIC editor lists all parameters of a cooked parent under "Global Scalar/Vector/Texture Parameters"; cooked data carries no group names. A cooked UMaterial opens in the Material Editor as a root node only (no expression graph).
- Every cooked `MaterialInstance` export ends with an int32 count and raw variant configurators; the `dbd.material_instance_trailing_variants` post-serialize handler reads them.
