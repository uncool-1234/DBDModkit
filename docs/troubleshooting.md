# Troubleshooting

Logs: `<project>\Saved\Logs\DBDMount.log` (or the `-log` window). Symptom, cause, fix.

| Symptom | Cause and fix |
|---|---|
| Editor starts as plain UE, no `LogModkit` lines; `LogSuzie: Suzie idle: no profile selected` | No profile selected. `ModkitData\ModkitLocal.ini` is missing or has no `Profile=` (open the project and fill in the setup window), or `Profile=` is not a profile folder: it must be the folder that contains `profile.json` and `engine.ini` (for example `.../Profiles/DBD`), not the file `profile.json`. `-DisableModkit` also causes it. |
| 0 containers mounted, `failed to fill whole buffer` or index errors | Wrong `GameRoot`, wrong or missing key, or a game version other than the one the build matches. Stock tools cannot read the containers; only this engine's cipher from `engine.ini` can. |
| `LogModkit ... key file` error | `KeyFile=` path is wrong or the file does not hold `0x` + 64 hex digits. The value is never logged. |
| Materials render as the default/grey material, `Incomplete material` | `r.AllowStaticLighting=False` is missing in `Config/DefaultEngine.ini`, or the editor runs with SM6/Vulkan: start with `-d3d12 -sm5`. `missing TShadowDepthPS...` on `M_CAMPER`, `M_CAMPER_CUST`, `M_Slasher` or `M_Slasher_Burn` is expected (permutations the game did not cook). |
| `Incomplete material X, missing (TBasePassPSFNoLightMapPolicySkylight)` or `FDeferredDecalEmissivePS`; lit opaque or decal materials draw as the default material | The renderer settings of the project template are missing in `Config/DefaultEngine.ini`: `r.SupportStationarySkylight=False`, `r.SupportLowQualityLightmaps=False`, `r.DBuffer=False` next to `r.AllowStaticLighting=False` ([profile-format.md](profile-format.md#project-requirements)). |
| `Modkit: '<calling function path>' calls a function this editor does not have; script aborted.` | A Blueprint calls a game function that did not resolve. The call's parameters are evaluated and discarded, and the script stops with a logged Blueprint exception. Static functions of Blueprint function libraries without a native implementation are not generated ([native-type-generation.md](native-type-generation.md#engine-class-functions)). |
| `LogSuzie` warning naming an engine class function with a different signature | The game function has another signature than the editor's and no native implementation is registered. The editor signature is used; the five known cases are listed in [limitations.md](limitations.md). |
| `tolerating layout hash mismatch for FMaterialShaderMapContent / FMeshMaterialShaderMap` | Expected; the types are listed under `[ShaderLayout] TolerateMismatch`. |
| `Uniform buffer translation '<Layout>': ...` errors, or fewer than 24 of 24 layouts registered; layout hash ensures and access violations when materials draw | The profile's `uniform_layouts.txt` is missing or does not match this engine's uniform buffer structs (each error names the check that failed). The file is generated against the stock 5.7.4 editor layouts; regenerate it as in [game-update.md](game-update.md) step 4. |
| Many `Invalid GameplayTag` warnings | The jmap is missing or has no tag settings object, or the tags were written during this start and the redirects apply from the next start ([tags.md](tags.md)). |
| Crashes after a failed experiment, corrupt shader cache | Use the project DDC `<Project>\DDC` (the engine sets it for every project it opens, unless `UE-LocalDataCachePath` is already set), delete that folder and restart. Never share one DDC between the stock editor and this one. |
| `Plugin 'Suzie' ... duplicate` | The plugins are also copied into `<project>\Plugins` of an installed-engine project; remove them (they are engine plugins there). |
| `Missing or incompatible game module` | In a project made from the installed-engine template (`DBDMount-Template`, content only), the project has a `Source` folder or `Modules` entry: remove them from that project. The dev project `DBDMount` keeps its `Source` and module; build it with `DBDMountEditor` ([engine-fork.md](engine-fork.md)). |
| `Project was made with a different version` dialog, double click opens the wrong engine | The engine is not registered or registered under another id; run `Register Engine.bat` (in the root of the installed engine folder). |
| The `Modkit project setup` window opens when the project starts | A path is missing or invalid: `ModkitData\ModkitLocal.ini` is missing, has no `Profile=`, or the profile, the AES key file, the game folder or the jmap is not found. The window shows one row per path; fill in the invalid rows and choose `Save and restart`. The same problems are logged as a Warning (`LogSuzie`). |
| 15 to 30 minutes of nothing on first start | Normal: SM5 global shader compile with an empty DDC. Watch the `ShaderCompileWorker` processes. |
| Out of memory during shader compile | Close other programs; 16 GB RAM works. |
| Crash or `bIsOptional && ElementSize` assertion after a game update | The game version differs from the version of the jmap or of the build: unversioned data desynchronizes. Use the jmap of the running game version and follow [game-update.md](game-update.md). |
| `SchemaIt != SchemaEnd` assertion | A game class or struct has reflected members that the schema recipes derived from the jmap do not account for ([schema-shadow-properties.md](schema-shadow-properties.md)). |
| DataTable assertion in the unversioned loader for a row struct with a natively serialized struct (`BarkRuleDB`) | The `DBDModkitGame` plugin did not load: check it is enabled in the `.uproject` and `LogSuzie` names the extension module. |
| `Suzie idle: profile '<id>' needs the game's jmap, ...` | `Jmap=` under `[Local]` in `<Project>\ModkitData\ModkitLocal.ini` is missing or names a file that does not exist: put the jmap in `<Project>\ModkitData` and open the project to fill the `Jmap` row, or pass `-SuzieJmap=<file>` ([jmap-usmap.md](jmap-usmap.md)). |
| Editor start takes about 9 seconds longer than a stock start | Suzie parses the jmap at every start (180 MB for DBD 10.2.2). |
| `GENERATE FAILED: no jmap` | `Suzie.GenerateNativeTypes` found no jmap: same cause as the idle line above. |
| The sweep tools do not find the engine | Set `EngineDir=` in `ModkitLocal.ini` to the folder that contains `Engine`, or make the `.uproject` `EngineAssociation` a path or a registered engine id (`Register Engine.bat`). Dev tree: check `MODKIT_ROOT` (`tools\env\modkit-env.cmd`). |
| After moving the tree: plugins missing, worktree errors | Recreate the junctions `DBDMount\Plugins\Suzie` and `DBDMount\Plugins\DBDModkitGame` (`mklink /J`), run `git worktree repair` in the engine fork, delete `Intermediate` folders and rebuild, then open the project so the setup window can check its paths. |
| The setup window shows a row as invalid | The engine, the game or a data file moved: fill in the row and choose `Save and restart`. Two files with the same extension in `<Project>\ModkitData` (`*.txt`, `*.jmap`) leave the row invalid: keep one per extension. |
